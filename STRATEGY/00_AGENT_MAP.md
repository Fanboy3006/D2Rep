# DOTA 分析项目 · 总纲（AGENT MAP）

> **用途**：本 project 从"单线深挖"升级为多会话协作。为保证每个会话的**上下文纯净**（互不污染、各司其职），现将项目拆分为**三层专业会话 + 一个总控接口**。本文档是所有会话的"地图"：**每个会话先读本文档，再读自己那一层的文档**。

## 0. 总体结构

```
                        ┌─────────────────────┐
                        │   总控 / 人机接口    │  （对外交流、汇集信息、定优先级）
                        └──────────┬──────────┘
           ┌──────────────────────┼──────────────────────┐
           ▼                      ▼                      ▼
   ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
   │  ① 地图复现层 │      │  ② 数据分析层 │      │  ③ 逻辑层     │
   │  (地图/坐标)  │      │  (代码/统计)  │      │  (问题/意义)  │
   └──────────────┘      └──────────────┘      └──────────────┘
```

**核心原则**：
- **各层上下文纯净** —— 一层只做一层的事，不横向越界。
- **单一真相源** —— 层与层之间通过协议文档交接，不做"跨层猜"。
- **逻辑层在上游** —— 数据层只回答逻辑层提出的问题；逻辑层不被"先有结论再找数据"绑架。

## 2. 如何使用（每个会话开场必读）

1. **先读 `00_AGENT_MAP.md`** —— 知道整体四层结构与自己所属层。
2. **再读自己那层的文档**（如地图层读 `01_MAP_REPLAY.md`）—— 明确边界、输入、输出、已知约束。
3. **跨层协作**一律走 `05_HANDOFF.md` 模板 + `06_QUESTION_BANK.md` 流转，**不靠会话记忆**。
4. **不要越界**：本层的问题在本层解决；发现需跨层 → 用交接模板，不在本层硬做。
