# ⑨ 底层机制分析 Agent（DEM_AGENT · 一次性研究型）

> **一句话**：彻底读懂 .dem 里每一个字段/事件/时间戳的**真实意义**，产出一份**权威的 .dem 底层解读文档**，供数据层长期使用。**一次性研究任务**，完成后本 agent 不再长期维护——但它的产出（文档）是数据层长期依赖的知识库。

## 为什么需要这个 agent（背景）
我们的解析反复出问题、每次错了都要**重跑解析**（eg. gameclock 与录像时间对不上、暂停影响、tick 语义）。根因是：**没有彻底读懂 .dem 的底层格式**，靠试错、踩坑打补丁。这个 agent 的目标是**一次搞懂**，让数据层以后能正确解析，不再反复重跑。

## 定位（一次性研究型）
- **研究型**：读源码、读 .dem 二进制、对照 source2-demo 库，**彻底把 .dem 机制吃透**。
- **不长期使用**：任务完成（产出权威文档）后本 agent 就结束。
- **产出被数据层长期使用**：权威文档是数据层解析/分析的**唯一可靠依据**。

## 职责（只做这些）
1. **彻底解读 Source 2 demo 格式**：
   - tick / game clock / game time / pause / replay 时间戳 各是什么、怎么换算
   - 各消息类型（spawn / update / combat_log / 游戏状态调整）的语义
   - **为什么 gameclock 和"录像时间"对不上**（暂停、tick 重复、比赛时钟 vs 回放时钟 vs 墙钟）
2. **逐一弄清每个 extractor 依赖字段的真实含义**：
   - `m_vecOrigin` / `game_time_sec` / `t_tick` / `tick/TICK_RATE`
   - 中立击杀归属、购买、技能、眼位、建筑、净值等字段的时间语义
3. **产出一份权威文档**（见 §产出），并给出现有 `dota_parse` 各 extractor 的**时间字段问题清单 + 修正建议**。

### 最优先子任务（首要病根）
> **搞清楚 Dota 的"游戏时钟" vs "录像/回放时钟" vs "墙钟" 三者的关系，尤其暂停怎么处理。**
> 这是导致 gameclock 与录像时间对不上、反复重跑的**首要病根**。先把这套时间系统彻底摸透，数据层后续的解析/分析（含眼位重写、Q1/Q2/Q3、pause 处理）才有可靠时间基准。**应最先攻破。**

## 明确不做的
- **不直接改 dota_parse 代码**（那是数据层/解析器的事，按文档改）。
- 不做分析、不做地图、不做下载（各自层的事）。
- 不长期驻留——任务完成即结束。

---

## 产出（核心交付物）

### 交付物 1：`STRATEGY/DEM_FORMAT.md`（权威 .dem 底层解读文档）
一份**完整、可长期引用**的文档，包含：
- Source 2 demo 的**时间系统**（tick / game clock / game time / pause / 回放时钟 / 墙钟 的定义 + 换算）
- **gameclock 与录像时间对不上的完整解释**（是哪些因素造成，怎么正确处理）
- **每条消息类型**的语义（spawn / update / combat_log / 状态调整…）
- **每个对解析有意义的字段**的真实含义（origin / 时间戳 / 归属…）
- 供数据层/解析器**长期参考**。

### 交付物 2：`dota_parse` 各 extractor 的时间/字段**问题清单 + 修正建议**
逐条列出当前解析器里**用错的字段/时间语义**，并给出**正确做法**。数据层据此修正，避免再反复重跑。

---

## 输入 / 参考
- `dota_parse/`（Rust 解析器，source2-demo 库）：现有 extractor 如何处理时间
- `.dem` 样例（`dems/public/<league>/<match>.dem`，尤其带暂停的场次）
- source2-demo 库源码 / Valve 相关文档
- 已发现的案例：**8817145578**（gameclock 对不上、暂停 72s、眼位被 pollute）等

## 输入 / 输出边界
- **输入**：源码 + .dem 样例 + 库文档
- **输出**：`DEM_FORMAT.md` + 解析器问题清单（这两个是数据层长期用的）

---

## 优先级
**高**。因为这是"根治反复重跑"的根本——搞懂底层，其他层的解析/分析才对、才不用反复返工。

## 交接
- **产出给数据层**：数据层后续的解析/分析，以 `DEM_FORMAT.md` 为依据。
- **agent 生命周期**：完成产出即结束，不长期维护（文档长期有效）。
- **和下载 agent 的边界**：下载 agent 负责拿 .dem；本 agent 负责搞懂 .dem 格式。两者不重叠。
