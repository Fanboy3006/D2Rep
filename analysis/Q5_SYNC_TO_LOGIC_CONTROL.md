## 〇、一句话给总控
眼位研究统计的是"位置",但**原解析器从一开始就没给眼位存"身份"和"坐标"**,导致所有眼位数据只能靠时间顺序猜测配对(LIFO)、在含 pause 的场次必然配错。本次**重写了 ward 解析组件**,每支眼现在有唯一实体身份 + 真实逐秒坐标 + 真实生命周期,并修复了时间口径。**已全量重解析 970 场并跑通 Q5/Q5B。**

## 一、根因(设计缺陷,已确认)
- 原 `WardExtractor` 只在放置时记 `type/x/y/team`,**未记每支眼的实体 index**;销毁走战斗日志 Death,**无坐标、无 index**。
- 后果:Q5 只能靠 `(team, ward_type)` + 时间顺序配对硬配,无法区分"哪支眼是哪支眼",也无法正确统计"真眼位置"。
- 对照:**同一解析器里的建筑/野怪提取器早已正确用 `entity.index()` 按实例跟踪**,唯独 ward 组件缺失这三样(身份/逐秒位置/销毁坐标)。
- 影响面:Q5 眼位数据整体不可信;**Q1/Q2/Q3** 主要依赖净值/金币/英雄位置,与 ward 无关,应**不受影响**。

## 二、已实施修复(② 数据层已落地)
1. **`WardExtractor` 重写为"实体跟踪"**:
   - 放置:`ward_placed` 记录 `entity_index`(每支眼唯一身份)+ 坐标;
   - 逐秒:`entity_snapshots` 新增 `entity_type='ward'`、`entity_id='ward:<index>'`,逐秒真实坐标;
   - 销毁:`ward_destroyed` 带**坐标**(取自该眼实体消失处)+ `entity_index`。
2. **时间口径**:
   - `game_start`(0:00 号角)= `min(building_spawn) + 90`(塔/建筑在预赛阶段 -1:30 生成,号角 = +90s)。970 场全部命中 building_spawn,无回退。
   - 同一 raw 时钟(tick/TICK_RATE)贯穿 placed/entity/destroy,消除两套时钟混淆。
3. **销毁判定(混合方案)**:
   - **自然到期(expired)** = 放置 + 标准寿命(**真眼 420s / 假眼 360s**)。
   - **被反(dewarded)** = 该眼**提前消失**(entity last_t < 放置+寿命)且存在同队同型 combat-log `dewarded` 死亡,其 `t_tick` 与该眼 last_t 差 ≤12s。
   - 不再用 "LIFO/FIFO 时间配对"。
4. **被反判定关键**:combat-log `dewarded` 事件现在带 `t_tick`(= raw 时钟),与眼实体 last_t 同源,实测差仅 0~12s。**因此能可靠确定"反的是哪支眼"**。

## 五、指标口径(反眼率只算反假眼)
- **反眼率(核心)** = 每支真眼**平均反掉的敌方假眼数**(avg_jy)—— 热力默认指标。**不含反真眼、不含真眼自己被反**。
- **其它微调指标** = 平均反真眼(avg_zy)/ 平均总反眼(avg_all, 含反真眼, 非核心口径)。
- **总反眼数** = 该格全部真眼**累计**反掉的眼数(总反假眼数 jy_total / 总反真眼数 zy_total / 总反眼数 all_total = jy+zy)。
- 明细钻取里的**反眼率** = "反到≥1个敌方假眼的真眼占比"(只用 success, 不含反真眼)。
- **按队伍(天辉/夜魇)+ 时间窗(-1:30-7 / 7-15 / 15+)** 分开统计。
- 位置 = 真眼放置点的 100×100 格(172 单位,`MAP_HALF=8600` 保全图)。

## 五·B、【大发现】per-ward 实体数据让"反眼归属/被反眼位置"变为真实
- 每支真眼现在记录**被反假眼/真眼的位置列表** `dew_obs_pos` / `dew_sen_pos`,每项 `[x, y, 游戏时钟, 被反眼阵营, 反眼队伍阵营]`。
- 由此 Q5B 查看器能**在地图上精确标出"这支真眼反掉了哪些敌方假眼(绿)/真眼(红)"**,供回录像核对。
